## Implemented read-only contract

`event-capacity-historical-github-reader.js` provides a separately configured private GitHub Contents API reader for the existing offline encrypted archive codec. It has **no production workflow import, writes, event approval, Discord call, scheduled action, channel edit, or automatic availability certification**.

The archive stored in the private repository would have this layout:

- `capacity-history/current.json`: `{"version":1,"manifest":{...}}` containing only the **private** encrypted archive manifest, no plaintext event records.
- `capacity-history/segments/<sha256-of-ciphertext>.bin`: raw encrypted segment bytes with the filename fixed by SHA-256 content digest.

The reader checks:
1. An exact, explicitly configured repository name (public Kings code repository is prohibited), actual GitHub metadata with `private:true`, unarchived `main` and expected repository identity.
2. A separately retained, **offline Ed25519 owner-signed archive checkpoint** binding guild, forum, revision, journal tip, SHA-256 of the archive manifest and issuance timestamp. The receipt cannot be generated by reading the GitHub archive itself. An owner/public verification key is required; the owner **private signing key must never be placed in GitHub Actions/Discord/public Git**, including the test/review environment.
3. Exact bounded GitHub Contents responses and Git blob SHA1 verification; segment path names are deterministically constructed from authenticated manifest digest strings, never supplied by a Discord member.
4. Every segment ciphertext SHA-256, part length, bounded transfer, AES-256-GCM authentication, all historical owner signatures, entry chain continuity and archive checkpoint matching.
5. The `current.json` index is read before and after the segment downloads and must be **exactly the same Git blob**; repository metadata is rechecked.
6. On any missing object, changed index, invalid archive, revoked/wrong key, wrong checkpoint or permission uncertainty: **fail closed**, with only a generic public-safe error.

All requests made by this reader are **GET only**. The reader does not create the initial encrypted archive and cannot persist updates itself. It is a preparation for durable storage, not a claim that durable storage has been provisioned. Even a fully intact archive returns `historicalCoverageCertified:false`, `sourceEvidenceAuthenticityVerified:false`, `freeSlotsCertified:false`.

## Offline owner receipt

`issueHistoricalArchivePinOffline` can sign an archive revision with an Ed25519 key in an **independent offline owner-controlled environment**. The format is domain-separated from event transition signatures, to prevent inadvertently treating a history archive receipt as a different decision approval. `verifyHistoricalArchivePin` checks the receipt with the corresponding public key.

A valid signed receipt **only binds the exact revision held by the operator**. It does *not* independently know whether a later receipt exists, whether old Convoy Center events are missing, or whether the original archived thread source is authentic. Latest-revision assurance needs a separately controlled, updated authoritative owner highwater, plus the independent private checkpoint/witness system and operator reconciliation.
